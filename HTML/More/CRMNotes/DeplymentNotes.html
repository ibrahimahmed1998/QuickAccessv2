CRM deployment notes

Field Deletion Checklist

Steps to follow before removing a field from a CRM solution, to avoid breaking dependent views, forms, workflows, and reports.

Backup first

Take an on-demand environment backup from the Power Platform admin center and export the affected solution (managed and unmanaged) before changing anything. Label it with the date and change name so you can restore quickly if something breaks.

Backup confirmed → continue No backup → do not deploy

Stop SMS activities and plugins

Before deploying, deactivate SMS-sending workflows, Power Automate flows, and plugin steps (Plugin Registration Tool → disable step) so customers don't receive duplicate or test messages while data is imported or migrated. Note every component you disable.

After deployment → re-enable each step Then send one test SMS to verify

Run Advanced Find on the field

Before deleting a field, use Advanced Find to check whether it is referenced anywhere — views, forms, business rules, workflows, plugins, or reports.

Used → migrate before deleting Not used → safe to delete

If it is used, plan the migration

Identify the new field that will replace it and migrate existing data and references into that field before removing the old one.

Verify usage first, migrate safely, then remove.
