Requirements

  1. Include everything that was explained throughout the session. Do not omit, summarize, shorten, or skip any explanation, example, definition, note, warning, code explanation, or important detail.
  2. Preserve the explanations from beginning to end and in the same logical order as they appeared in the session.

    • Arabic text should use Right-to-Left (RTL) direction.
    • English text and code should remain Left-to-Right (LTR).
    • Keep Arabic and English text readable without reversing English words, technical terms, or code.
  5. Preserve all technical terms, programming keywords, commands, class names, method names, variable names, URLs, file names, and code snippets exactly as they appeared.
  6. Keep all examples and explanations intact. Do not replace detailed explanations with brief summaries.
  7. Use clear document formatting:
    • Main title
    • Section headings
    • Subheadings
    • Bullet points
    • Numbered lists
    • Code blocks where applicable
    • Tables where they improve readability
  8. Do not remove repeated explanations if they were intentionally part of the original session. The goal is to preserve the complete explanation, not to create a shortened summary.
  9. Make the Word document professional, readable, and suitable for future study or reference.
  10. Ensure the final .docx file is generated successfully and provide the download link to the completed Word document.
Important: The first visible text in the Word document must be AR.
This is specifically required to preserve proper RTL behavior when opening the document in Microsoft Word.
